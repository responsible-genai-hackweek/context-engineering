snowexsql — A Python library
for the SnowEx database

NASA SnowEx campaigns — multi-year field and airborne snow measurements across western US and Alaska

PostgreSQL/PostGIS database — snow depths, density, temperature, stratigraphy, SWE

Python package — query via a Lambda client (no credentials) or direct DB connection

Returns DataFrames — filters by campaign, date, type, location

Clone the forked repo: github.com/jomey/snowexsql — Hint: Agents cheat!

How to guide the LLM with context?
Add a central context document

"Think of AGENTS.md as a README for agents: a dedicated, predictable place to provide the context and instructions to help AI coding agents"

agents.md

A good AGENTS.md is concise and actionable

Start simple Expand as needed over time
Be specific Not "follow best practices" — instead Run lint after every change
Keep it short Under 200 lines or 32 KiB
Nest for big repos The "closest" AGENTS.md wins
It's a guide, not enforcement No guarantee "DO NOT EDIT" is honored
Keep human docs in README LLMs will read that too

The db-query skill

name: db-query
description: "Query the SnowEx database
  for layer or point data"

instructions:
  1. Use the simple API (not raw SQL)
  2. Connect with db_session()
  3. Use LayerData for profiles,
     PointData for single values
  4. Filter with campaign=, date=
  5. Return as DataFrame

Always-on context vs. on-demand procedure

Context document

Information needed regardless of task — structure, vocabulary, conventions

Skill

A specific procedure that only applies to certain tasks — querying the DB, running tests

Create bridges to skills in the AGENTS.md so the LLM knows about them

Context engineering is the
researcher's primary lever

1 The model's built-in knowledge ends at your project boundary
2 Domain knowledge of your work must be engineered in
3 Add context as you observe LLM behavior
4 Choose the mechanism that matches how broadly the context applies
